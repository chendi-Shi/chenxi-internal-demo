# 买方分析师工作台优化报告

日期：2026-09-24

## 采用的研究框架

界面信息架构以用户提供的 prompt skill `Facts_商业模式和财务数据` 为主线。第一阶段只改变检索工作区的视觉层级和使用路径，不生成财务数据、不调用模型，也不扩展上游契约。

## 第一阶段完成内容

- 将营销型大标题页面改为高信息密度的买方研究工作台。
- 顶部固定展示研究视角、排序责任和内容信任边界。
- 将环境连接、资料库状态与数据源压缩为可快速扫描的区域。
- 左栏集中显示来源权重、新文档加成、时间半衰期和策略版本。
- 中栏集中显示查询、单次过滤、服务端结果和排名变化。
- 打开文档后形成右侧全文栏，研究者可同时核对策略、排名和证据。
- 保留所有原有 DOM 行为和 API 边界，不增加客户端 ranking。
- 文案使用直接的研究术语，去除装饰性标题和箭头。

## 浏览器验收

在官方虚构 fixture 和 1674×854 浏览器视口中验证：

1. 页面载入 2 个来源、2 个文档和 Policy v1。
2. 初始工作区为 330px 策略栏和 1261px 查询/证据栏，无水平溢出。
3. 查询“芯片”后返回两条 v1 服务端顺序结果。
4. 打开全文后布局为 310px 策略、约 713px 证据、约 556px 文档三栏，无水平溢出。
5. 正文和 metadata 按纯文本展示，`content_trust` 保留。
6. 保存示例策略后 Policy 与状态同时变为 v2。
7. 公司公告上升一位且来源权重为 3.00；研究纪要下降一位且来源权重为 0.50。
8. 搜索按钮、策略版本和排名变化文案保持一致。

## 第二阶段完成内容

- 新增商业模式、八季度变化、利润与现金流、竞争力、风险和跟踪指标六个研究主题。
- 研究主题只填充简短全文查询，不自动执行搜索或调用模型。
- Fixture 模式保留“芯片”基线入口，并明确提示其他主题需要真实上游。
- 从已读取文档的 `metadata.attributes` 动态生成下一次查询的精确过滤建议。
- 复用 metadata 时替换同名键、自动展开单次查询过滤区，不修改持久 Policy。
- metadata 建议只接受安全的单行 `key=value`；含换行或非法键名的不可信 attributes 不进入按钮。

浏览器验收确认：六个主题按钮可用；选择“商业模式”只更新查询、不产生隐式结果；恢复 Fixture 基线后搜索仍返回两条服务端结果；打开文档后出现 `company=虚构公司` 与 `sector=科技`，点击公司属性后精确写入过滤文本并展开过滤区，无水平溢出。

## 第三阶段完成内容

- 策略输入变化后显示待保存摘要，包括来源名称、字段、原值和新值。
- 摘要只比较用户输入，不计算 score 或预测排名。
- 无变化时不显示摘要，保存成功并载入新 PolicyState 后自动清除。
- 浏览器验收确认示例策略准确列出两项来源权重变化，保存至 Policy v2 后摘要隐藏且页面无水平溢出。
