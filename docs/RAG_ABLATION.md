# RAG 检索消融：方法、复现与证据边界

本轮工作日期：2026-10-15。基线源码为 `03a042a9fded6f8be414d171a4f62df97a3797e5`。

本项目实现的是 RAG 的文档接入、检索、排序与取证工具层，没有固定的回答生成器。因此本实验衡量“证据是否被找回、排在何处、返回成本如何”，不把检索 Recall 或 nDCG 写成回答准确率、faithfulness 或 hallucination rate。

## 2. 从“串联六阶段”到可归因的消融

旧链路为 lexical、dense、normalized hybrid、RRF、RRF + rerank、RRF + rewrite + rerank。前两项是独立基线，normalized 与 RRF 是替代融合算法。不能把每一相邻行都称为“新增组件收益”。

新 PostgreSQL 矩阵按以下假设组织，具体参数以 JSON 为准：

- **召回通道**：固定融合与下游配置，比较双通道、移除 dense、移除 lexical。向量覆盖不完整时，dense 的变化同时受可搜索语料范围影响，不能归因于模型能力。
- **融合方法**：固定同一候选预算，比较归一化加和与 RRF；扫描 RRF 平滑常数。分数尺度不同是使用 RRF 的动机，不构成它一定更优的证据。
- **rewrite × rerank 的 2×2 设计**：分别运行二者都关闭、只 rewrite、只 rerank、二者都开启。rewrite 使用已有确定性双语规则，并保留原 query；不是 LLM 改写。
- **候选与重排预算**：单因素改变每路候选数和重排文档数，记录池大小与实际评分数。预算是上限，语料不足时实际数量不会达到上限。
- **输出 top-k**：分别计算 @1、@3、@5、@10；不能把更大的返回列表带来的 recall 增长解释为排序提升。

对于每题指标 `m`，rewrite/rerank 交互为：

```text
interaction = m(rewrite + rerank) - m(rewrite only)
              - m(rerank only) + m(neither)
```

只有四个配置使用同一快照、查询、标签与健康运行结果时才适合计算。历史链路缺少 `rewrite only`，不能补算这个交互。

SQLite 实验检验现有系统的查询规划和策略层。关闭词汇扩展或标题守卫只发生在隔离的离线进程和虚构数据库中；来源启用状态及请求过滤仍由实际服务代码执行。来源权重实验是偏好干预，不是学习得到的相关性模型。新鲜度实验固定“当前时间”，避免日期变化成为隐藏变量。

## 3. 指标与统计单位

以文档 ID 为检索单位，同一文档的多个 passage 不重复算命中。对有答案问题计算：

- `Recall@k = top-k 中正相关文档数 / qrels 中所有正相关文档数`。
- `MRR@k = 首个正相关文档排名的倒数`，没有命中时为 0。
- `nDCG@k` 使用 `2^grade - 1` 增益和 `log2(rank + 1)` 折扣。

无答案过滤控制单独报告非空返回率及成功空结果数，不混入有答案问题的平均值。查询失败返回空列表不能视作正确拒答。这里的负例是 impossible-filter 控制，不是语义无答案检测。

同一题重复运行用于观察时延波动与排序稳定性。质量统计先折叠同一题的重复，再按 query 配对，不能把 20 题 × 3 轮写成 60 个独立质量样本。配对 bootstrap 对题目差值重采样，固定随机种子，报告百分位区间及胜/平/负；语言切片的样本更小，应同时查看逐题结果。

这些区间仅描述所给题集内的重采样不确定性。题目和文档是人工构造的固定 fixture，未独立随机抽样；大量配置的探索性比较也没有多重检验校正。因此不据此宣称总体显著优越，也不依据这批结果自动替换生产配置。

## 4. 成本、错误与复现

记录运行环境、固定时钟、随机种子、配置、数据/源码 SHA-256、预热和重复次数。时延报告 median/p95；预热单独统计，失败与降级不能被静默排除。新实验随机化执行顺序，仍属于单机诊断，不是负载测试或部署容量承诺。

SQLite 的 UTF-8 JSON 响应字节衡量接口载荷，不能直接等同于模型 token 或账单。PostgreSQL 实验的局部时延仅覆盖实际执行的检索/改写/重排，不包含 ChatGPT 调度、网络或答案生成。历史报告的固定阶段顺序、共享 CPU 与冷启动限制仍然适用。

公开产物使用仓库虚构数据、既有匿名汇总或注明来源的公开基准指标。所有原始下载、模型、缓存、逐题轨迹均放在忽略目录 `backend/artifacts/` 或 `backend/data/`。私有库的 query、document ID、片段、本地路径不可直接提交。公开基准发布聚合指标、配置及可复现的案例 ID，不把原始语料或模型文件复制到仓库。

## 5. 仍需独立实验的维度

| 维度 | 当前状态 | 下一次实验控制 |
|---|---|---|
| 全量 vs 部分向量覆盖 | 原私有库覆盖仅 6.74%，本次未重建；公开实验要求完整语料编码 | 公开全覆盖结果不能直接与私有部分覆盖结果相减；同一语料上的覆盖子集实验需另设控制 |
| 分块长度、重叠、按页/按段分块 | 本次不改生产 1400 字符/160 重叠 | 使用含长文和跨边界证据的独立语料，每组重新建库和编码；同时评估 passage 证据覆盖 |
| 多语言 reranker 替换 | 已列入公开 GPU 矩阵；原私有库仍只有历史 English MS MARCO MiniLM 证据 | 相同候选池、硬件和 token 上限；锁定模型版本，不根据测试集选模型 |
| ANN 与 exact cosine | 现有 PostgreSQL 为 exact baseline | 固定向量快照，单独测近邻召回率、检索质量和并发时延 |
| 答案生成与引用支撑 | 仓库没有固定生成器 | 固定 generator/prompt/context budget/seed，独立评估答案正确性、引用支撑和无答案拒答 |
| 泛化能力 | 虚构题集是诊断集；公开 SciFact/FiQA 使用 test，T2 使用固定 dev 子集 | 不依据 test 结果选择配置再宣称独立测试提升；另行保留业务测试集 |

这些项目均不以占位数值充当实验结果。当前结果适合发现回归、识别负增益和验证实验链路；真实业务配置应由独立受控测试集决定。
