# SQLite RAG 检索消融：真实 Hub 执行、公开虚构样例

运行时间：2026-10-15T07:24:38+00:00。固定新鲜度时钟：2026-10-15T00:00:00+00:00。

本报告实跑 `17` 个配置 × `20` 个问题 × `5` 轮，共 `1700` 次正式 `Hub.search`；另有 `340` 次预热。全部使用新建临时 SQLite 数据库，真实 ingest `26` 篇虚构文档，形成 `26` 个 chunk。
没有生成模型、embedding、reranker、PostgreSQL 服务或网络调用；结论只覆盖当前 SQLite 词法检索。

## 方法与边界

- 复用 `backend/samples/postgres_synthetic/suite.json` 的固定正文与 qrels，未根据本次排序重标。生产 ingest 返回的哈希文档 ID 经显式映射后再与 fixture qrels 比较；映射写入 JSON。
- 中性基线使用原生产双语 planner、FTS5 BM25、来源权重 1、recency_boost=0、half_life_days=90、top-k=10。`recency_025` 才对应生产默认新鲜度配置。
- 组件关闭只通过测试作用域内的 planner patch 实现。评分、分块、过滤、去重、排序与 top-k 全部调用现有生产代码。每个配置独立数据库，策略通过乐观锁保存；每条结果检查 policy_version。
- 所有来源/date/metadata 查询过滤保持原样；disabled source 始终禁用。返回值逐条校验过滤与来源边界。关闭 title guard 仅移除 planner 的标题实体/日期判断，不移除请求过滤或访问边界。
- raw OR/AND 是替换整个 planner 的复合对照，不能把它们的差值归因于某一个组件。half-life 的单变量参考是 recency_1，其他配置参考 baseline。
- 每一轮随机打乱配置与问题的笛卡尔积，预热轮不入统计；固定随机种子和完整执行顺序写入 JSON。计时只包围 Hub.search（包括 planner），不包括 ingest、策略保存、patch 建立、结果校验及序列化。
- Recall/MRR/nDCG 在 k=1/3/5/10 统计，仅包含 16 个有答案问题；4 个无答案过滤问题单列正确空返回率。MRR 截断于 k，nDCG gain=2^grade−1；未返回或未标注文档按 0 计。top-k 较小也保留相同评估截断。
- 先在问题内平均重复，再对问题宏平均。95% CI 对配对问题差值做 5,000 次 percentile bootstrap；重复次数不扩大质量样本量。W/T/L 也按问题计数；多个比较未校正，CI 仅作探索性不确定性描述。
- payload 是完整详细 SearchResponse 的紧凑 UTF-8 JSON 字节数，包含动态 elapsed_ms；不是模型 tokenizer、HTTP 线缆开销或生成 token。只评估检索，不评估答案生成、事实正确性或真实全库质量。

## 健康检查与可复现性

正式调用失败 **0**、带 warning 的调用 **0**、跨轮排名不稳定的问题/配置 **0**。预热失败 **0**、预热 warning **0**。失败调用不会被当作正确空返回；有答案失败计零并保留失败标志。

运行环境：Python 3.12.10，SQLite 3.49.1，Pydantic 2.13.5，Windows / AMD64。这是微型本地热缓存诊断，p95 不代表并发吞吐、冷启动或生产 SLO；其他进程会影响延迟。

```powershell
cd backend
python -m pip install -e '.[dev]'
python benchmarks/run_sqlite_ablation.py
python -m pytest tests/test_sqlite_ablation.py
```

默认读取公开 suite 与 sqlite_matrix，写入本目录 JSON/Markdown。可用 `--output` 与 `--markdown` 写到独立位置。矩阵中种子、轮次、bootstrap 次数、固定时钟和全部变体均显式配置。每次重跑质量指标应稳定，墙钟耗时与 payload 中 elapsed_ms 导致的少量字节变化属正常。

## 后续证据缺口

- 26 篇短文均为单 chunk，不能测出 chunk 大小/重叠、长文 citation 覆盖或跨段证据拼接的贡献。
- 中文问题/英文正文的词汇鸿沟需要独立标注集与真实模型实验；本次没有伪造 dense/hybrid/rerank 结果。
- 需要更大、盲标、各来源正例均衡的测试集和独立验证集，才能调权重与半衰期。
- PostgreSQL 既有实验、向量覆盖及生成答案质量必须单独评估，不能与此微型 SQLite 表格直接横比。
